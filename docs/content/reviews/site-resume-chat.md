# Review record: Resume-chat button

- **Piece:** `content/site/resume-chat.ts` -> `RESUME_CHAT_CONTENT.label`, change `app-home-resume-chat`, phase `site-ci-gates-and-chat-polish`. Added at execute time on the operator's instruction: "Be sure to add in a button that allows the user to go straight to the chat view if there is history available from the home page."
- **String (draft):** "Continue your conversation". The first draft was "Continue your last conversation"; the pre-review below advised dropping "last" (ambiguous between most recent and final, and too close to the header link "Your conversations").
- **Reading of the instruction (recorded in the proposal):** "the chat view" is read as the visitor's most recent conversation, not the conversation list. The list already has the header link "Your conversations" (`docs/content/reviews/site-history-link.md`), which stays. If the operator meant the list, the button's target is a one-line change and the label would need to change with it.
- **Where it appears:** the public site build's front page only, as a link button directly under the AI disclosure lines below the composer (`src/components/site/resume-chat-link.tsx`, rendered by `src/pages/landing-page.tsx`). It goes to `/threads/<id>` of the saved conversation with the latest update time. It is absent when this browser holds no saved conversation, when the only conversations are unsaved drafts, before the saved conversations have been read, and on the app build.
- **What it must not claim:**
  - It must not say where the conversation is stored, for how long, or that it is private or secure. The About panel already says "Your conversations are stored in this browser"; this label adds no claim to that.
  - It must not imply an account, a login, a sync across devices, or that anything is restored from a server. The conversation opens from this browser's own database.
  - It must not promise the conversation can be continued by the agent with full memory of it. It opens the saved conversation; what the agent remembers of it is not stated.
  - It must not be worded as "resume" for a different conversation than the latest: the button opens the most recently updated saved one, and the singular "your conversation" must stay true for that one conversation. If the target ever changes, the wording changes.
  - No hype language, no exclamation mark, no marketing words ("seamlessly", "pick up where you left off" are avoided on purpose).
- **Claims checked against the system:**
  - "your conversation" (singular; the button opens the most recently updated one): the link target is `getLatestPersisted()` (`src/stores/thread-registry-store.ts`), the non-ephemeral thread with the greatest `updatedAt`. `src/pages/landing-page.site.test.tsx` checks one saved conversation, several (the latest wins, an unsaved newer draft is ignored), none, only a draft, not yet read, and the app build.
  - "Continue": the link opens `/threads/<id>`, where the conversation's stored messages are shown and the composer accepts a new message. The built-app end-to-end (`e2e/home-resume-chat.spec.ts`, real PGlite, UAR mock) saves a conversation, goes to `/`, clicks the button and expects that thread with its question and the finished reply on screen.
  - No new network request and no new storage: the button reads state the header link's hook already loaded; hovering or focusing it prefetches the thread route code, as the composer does.
- **Voice:** one sentence fragment, plain verb first, sentence case, no hype, no exclamation mark, no claim beyond the action.
- **Editorial pre-review (km-chief-content-officer), 2026-10-19:** advised CHANGE to "Continue your conversation": no exclamation mark, no banned words, no storage, privacy or agent claim; "last" is ambiguous and the draft collides with the header link wording; "Pick up where you left off" rejected as longer and as implying a position within the conversation. The officer read the two content files only, not the voice guide or claims register in that pass. The advice is applied. This is not the operator's approval.
- **Operator approval: not given.** Status: pre-review pending. The string ships only through a product-owner change the operator approves and merges; the merge is the approval, as for earlier strings, and is recorded here once it happens.

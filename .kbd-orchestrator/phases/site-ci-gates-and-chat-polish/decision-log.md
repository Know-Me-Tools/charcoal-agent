## D-012 · Register change 7 app-persist-loss (execute, 2026-10-19)
- **Decision:** add change `app-persist-loss` (tasks 1.1 to 1.3) and scenario PERS-2; contract re-adopted (digest cc53bbc8, supersedes 3d2954ff).
- **Why:** the saved-conversation end-to-end for the front-page button failed in about 13% of runs (14 of 110) with PR #137 merged. Cause found with log evidence: `useDbHydration` runs in `AppLayout`, not on the front page; when the stored-threads read returns after the first reply, `initFromDb` overwrote the in-memory thread (already promoted by `markPersisted`) with the older stored ephemeral copy, and the title write then saved that copy as `is_ephemeral=true`, so the conversation is never listed. The operator's "Fix it" covers it.
- **Fix:** `initFromDb` adds only threads the registry does not already hold.
- **Alternatives rejected:** a retry or wait in the spec (hides a product defect); a fixed sleep before reload (the 3 s run still failed).
- **Falsifier:** the 40x4 repeat of `home-resume-chat.spec.ts` on the fixed build still shows an ephemeral stored thread.
- **Review:** none independent (standing skip, recorded `pending_review`).

- **D-013 (lead, reflect time, 2026-10-21; supersedes the last sentence of D-008):** "GitHub runners were slow to pick up jobs on 2026-10-19" is withdrawn. `ci-runs.md` shows `gh run list` run-level status lagged while the jobs had finished; job timestamps from `gh run view --json jobs` are the reliable record. D-008's merge-order finding stands.

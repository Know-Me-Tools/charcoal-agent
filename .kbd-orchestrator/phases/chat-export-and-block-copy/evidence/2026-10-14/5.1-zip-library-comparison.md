## Decision (recommended; D-C in the decision log)

Use **fflate 0.8.3**, imported lazily, calling `zipSync` with `strToU8` for the sizes in scope (a few hundred small markdown files, a few MB). Reasons: MIT, no dependencies, ESM and types, a synchronous call that suits a Prepare-then-Save flow, a worker variant if slices must yield, and simpler than client-zip's BigInt and Zip64 behaviour. Fall back to a hand-written stored-entry writer (about 100 lines, UTF-8 filename flag bit 11, no Zip64 needed at these sizes) only if the real tree-shaken size or a real-iPhone problem says so.

`package.json` uses caret ranges and `versions.toml` pins no npm libraries, so adopting fflate means a deliberate `package.json` addition in change 5 (task 5.3), pinned to the exact reviewed version (`0.8.3`, no caret), with this file cited in the PR.

## Unverified

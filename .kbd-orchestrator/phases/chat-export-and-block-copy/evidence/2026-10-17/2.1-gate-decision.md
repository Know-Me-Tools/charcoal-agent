# 2.1 decision gate: site-stream-resume (2026-10-17)

**Decision: cancel the change.** Tasks 2.3 to 2.6 are cancelled; 2.2 (contract research) stays done. Decided by the lead on the operator's instruction of 2026-10-17 to finish the code and test later. The operator can reopen it.

The gate said: proceed only if streams die when the page is hidden, otherwise cancel.

## Reasons

1. **Resume cannot fix the page-hidden case.** `2.2-uar-resume-contract.md` records that UAR cancels a run 250 ms after its last subscriber drops. A phone that locks or backgrounds Safari drops the connection for seconds or minutes, so by the time the page is visible again the run is already cancelled and `x-uar-run-id` has nothing to replay. A resume would work only for a reconnect inside 250 ms. Whether a browser reconnect can reattach inside that grace was not traced, and a hidden page does not reconnect that fast.
2. **The stronger cause of unfinished replies was found and fixed server side.** Replies were ending about 62 s after the request because UAR's model client had a total 60 s deadline. The per-provider fix shipped in UAR v1.1.0 and is in production (`Built LLM client with effective request timeout timeout_secs=240`; whole-map diagrams complete in 35 to 50 s as Mermaid).
3. **The client-side causes are already addressed** by change 1 (coalesced deltas, memoized conversion, throttled markdown, no smooth scroll), merged and deployed in PR #103.
4. **The change is large and risky for the benefit:** a run-id token bound to visitor, thread and run; re-emitted `id:` lines through the filter; a metering path that does not reserve twice; a security review of replay. A 512-event ring and 10-minute retention also bound what it could ever fix.

## What this decision does not rest on

- The real-iPhone run (1.8) has not been done. If it shows streams dying when the page is hidden **and** the replies would otherwise have finished, that argues for a different remedy (keeping the run alive server side when the client disconnects, a UAR change), not for this resume path. The operator can reopen the change with that evidence.
- Task 1.1's logs were not re-read for this decision.

## Unverified

The 250 ms grace was read from the UAR source at commit `2cc9a182` (headers re-checked at `3e6af7c4`); it was not re-read at v1.1.0 and not measured in a browser.

# 1.5 Integration gate: saved-chats deleted notice (app-db-reset-notice)

Status: PASSED in Chromium against the built app, with one unexplained intermittent failure (see Flake). Not run in WebKit or Firefox; not run against the live site or a real UAR.

Updated 2026-10-19 after the content officer's pre-review: new wording ("Your saved chats could not be read, so they were deleted from this browser."), and the toast now stays until dismissed, with a close control.

## Method (task 1.1)

A damaged IndexedDB does not reach the path. The only message `DbProvider` matches ("bundle size") comes from `@electric-sql/pglite` 0.3.15, `getPreloadedPackage`: `Invalid FS bundle size: ${fetched.byteLength} !== ${expected}`. It checks the size of the fetched `pglite.data` asset, not stored data. In production this is a stale cached asset after a deploy.

The honest reach is therefore at the network boundary: Playwright serves a 1 KiB body for the first `pglite.data` request and passes later ones through. The real library throws, the real `DbProvider` purges `/pglite/charcoal-db` and reopens, the real app renders. Nothing in the app is mocked. The UAR backend is the suite's usual Playwright mock.

Limit: this proves the reset path and its notice. It does not prove that a corrupted IndexedDB triggers it.

## Run

- Build: `vite build` exit 0 (dist/ not committed). Serve: `vite preview --port 4392`.
- Spec: `e2e/db-reset-notice.spec.ts`, run with `E2E_PORT=4392 E2E_REUSE_SERVER=1`, Chromium project, one worker, no retries.

Result (last two full runs): `3 passed (45.6s)` and `3 passed (1.5m)`.
- `a normal start shows no reset notice`
- `... (desktop-dark)` at 1440x900 and `... (phone-320-light)` at 320x640, light theme: creates a saved thread through the real composer (at desktop width), reloads, serves the bad `pglite.data` once, reloads at the target width, then asserts: exactly one notice element, `pglite.data` requested exactly twice, thread gone from the sidebar (desktop only, the sidebar is hidden at 320); waits 6 s (longer than sonner's 4 s default) and asserts the notice is still visible with a "Close toast" button visible; clicks it and asserts the notice is gone; removes the fault, reloads, asserts no notice.

Unit: `src/lib/db/db-provider.test.tsx` also asserts the toast is called with `duration: Infinity`, `closeButton: true` and an id.
